# Стенд для показов (ДЗ 1, вариант 05)

Стенд: сеть, 2 подсети (ru-central1-b, ru-central1-d), N веб-серверов на порту 8015,
сервер приложения без публичного адреса, NAT-шлюз, сетевой балансировщик (порт 80).
Настройка машин — через cloud-init (cloud-init.tpl.yaml).

## Требования
Linux/WSL с bash, jq, curl, ssh; настроенный yc (проверка: yc config get folder-id);
SSH-ключ ~/.ssh/id_ed25519.pub; пустой каталог в облаке.

## Как поднять
    bash create.sh
Скрипт можно запускать повторно: существующие ресурсы пропускаются.
В конце он ждёт готовности и выводит результат check.sh.

## Параметры create.sh
Приоритет: аргумент > переменная окружения > умолчание.

| Аргумент | Переменная | Умолчание |
|---|---|---|
| --prefix | PREFIX | poeluev-05 |
| --zone-a / --zone-b | ZONE_A / ZONE_B | ru-central1-b / ru-central1-d |
| --cidr-a / --cidr-b | CIDR_A / CIDR_B | 10.15.1.0/24 / 10.15.2.0/24 |
| --port | SVC_PORT | 8015 |
| --word | WORD | vmlab |
| --web-count | WEB_COUNT | 2 (нужно не меньше 2) |
| --ssh-pub | SSH_PUB | ~/.ssh/id_ed25519.pub |

Пример: bash create.sh --web-count 3

## Как проверить
    bash check.sh; echo $?
Три проверки: балансировщик отвечает 200; ответы приходят больше чем с одной машины;
сервер приложения доступен с web-1 по внутреннему адресу. Код 0 — всё в норме, 1 — нет.

## Если check.sh вернул ошибку
- Первая строка красная: балансировщик не отвечает. Подождите 1–2 минуты после
  запуска или проверьте состояние целевой группы (yc load-balancer network-load-balancer
  target-states).
- Вторая красная: одна из машин не отвечает. Проверьте nginx на веб-серверах
  (sudo systemctl status nginx).
- Третья красная: у сервера приложения нет выхода в интернет (проверьте, что таблица
  маршрутов привязана к подсети a) или не пропускает трафик группа безопасности.

## Как снести
    bash destroy.sh
Удаляются все ресурсы с префиксом poeluev-05-. Проверка:
yc compute instance list; yc compute disk list; yc vpc address list.
